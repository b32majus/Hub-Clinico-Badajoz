## 2. CLOSED outcomes and boundaries
**#620 — IMPLEMENTATION APPROVED IN LOCAL ENVELOPE:**
- The supported `mostrarModalTexto(texto, titulo, mensaje)` in `modules/formController.js` currently has `fallbackCopy()` doing `document.execCommand('copy')` but dropping its boolean result. If the asynchronous `navigator.clipboard.writeText()` fails and fallback returns `false`, promise still resolves and app claims “Contenido copiado al portapapeles.” and closes the modal. It also happens when navigator clipboard is unavailable and `execCommand` returns false. This is a **pre-existing** flaw, separate from Train 18.
- On **confirmed successful API copy** or **`execCommand('copy') === true`**: one truthful success notification and normal modal close. On **`false`, rejection, or thrown copy exception**: *no success claim and no automatic close*, preserve original full modal text (textarea), allow retry/select/manual copy, show honest failure feedback without leaking content. Avoid false success on rapid/repeated attempts or stale in-flight completion; do not introduce a global clipboard manager. Preserve normal manually-triggered close/backdrop behavior.
