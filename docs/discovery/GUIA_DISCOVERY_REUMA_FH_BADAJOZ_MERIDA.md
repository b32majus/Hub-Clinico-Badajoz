# Guía de discovery — Interfaz Reumatología ↔ Farmacia Hospitalaria Badajoz / Mérida

**Fecha:** 2026-07-10  
**WO:** `WO-DOC-DECISION-DISCOVERY-REUMA-FH-POST-SES-01`  
**Ámbito:** Hospitales de Badajoz y Mérida (Reumatología, Farmacia Hospitalaria, Enfermería si aplica)  
**Estado:** Documento de trabajo; no define contratos finales ni autoriza integración  
**Nota sobre Cáceres:** El trabajo previo con Farmacia Hospitalaria de Cáceres se usa únicamente como referencia de aprendizaje. No se asume que el circuito de Cáceres defina los circuitos de Badajoz ni de Mérida.

---

## 1. Objetivo, alcance y reglas del discovery

### 1.1 Objetivo

Preparar una reunión de discovery con los equipos clínicos de Reumatología y Farmacia Hospitalaria de Badajoz y Mérida para entender:

- Cómo se solicita hoy una validación o actuación de Farmacia Hospitalaria desde Reumatología.
- Qué datos viajan, en qué formato y por qué canal.
- Quién toma cada decisión clínica/farmacéutica.
- Dónde se registra el acto profesional.
- Qué oportunidades existen para que el Hub digital apoye sin sustituir al profesional.

### 1.2 Alcance

- Reumatología → Farmacia Hospitalaria (solicitud de biológicos, validación farmacoterapéutica, seguimiento).
- Enfermería como nexo de coordinación cuando aplique.
- Circuitos de Badajoz y Mérida; se distinguen explícitamente si difieren.

### 1.3 Fuera de alcance

- No se definen campos finales de formularios.
- No se autoriza integración técnica, backend, producción ni datos reales.
- No se asume que el circuito de Cáceres sea el modelo a replicar.
- No se permite que el sistema infiera datos terapéuticos.

### 1.4 Reglas de la sesión

- Cada profesional es responsable de su área; el facilitador técnico no decide clínica ni farmacéuticamente.
- Lo que no se conozca del circuito actual se anota como hipótesis pendiente, no como requisito.
- Cualquier decisión de integración requiere WO posterior y validación de Sil/Cora.

## 3. Preguntas para Reumatología

### 3.1 Solicitud a Farmacia Hospitalaria

1. ¿Cuándo se solicita la actuación de Farmacia Hospitalaria? (inicio de biológico, cambio, renovación, incidencia)
2. ¿Quién en Reumatología inicia la solicitud (médico, enfermería, residente)?
3. ¿En qué sistema se hace hoy la solicitud? (JARA, orden clínica, papel, Excel, email, otro)
4. ¿Qué datos incluye de forma habitual la solicitud?
5. ¿Qué datos le faltan a Farmacia con frecuencia para poder validar?
6. ¿Existe un formato estándar de solicitud de biológico en el hospital?

### 3.2 Datos clínicos generados

7. ¿Qué scores/variables clínicas son relevantes para Farmacia al iniciar un biológico?
8. ¿Qué resultados de prebiológico se adjuntan o se esperan?
9. ¿Cómo se comunica el diagnóstico principal, comorbilidades y tratamientos previos?
10. ¿Se incluye justificación de la indicación o solo el fármaco solicitado?

### 3.3 Respuesta y seguimiento

11. ¿Cómo recibe Reumatología el resultado de la validación farmacéutica?
12. ¿Qué ocurre si Farmacia rechaza o solicita más información?
13. ¿Cómo se comunican cambios de pauta, suspensiones o efectos adversos?
14. ¿Quién decide el cambio terapéutico cuando hay incidencia: Reumatología, Farmacia o conjuntamente?

### 3.4 Dolor actual y riesgos

15. ¿Qué pasos del proceso actual generan retrasos o errores?
16. ¿Dónde se pierde información entre Reumatología y Farmacia?
17. ¿Qué temor o resistencia existe ante una digitalización parcial?

## 4. Preguntas para Farmacia Hospitalaria

### 4.1 Recepción de la solicitud

1. ¿Cómo llega hoy la solicitud desde Reumatología? (JARA, orden clínica, papel, email, Excel, teléfono)
2. ¿Qué datos mínimos necesita Farmacia para iniciar la validación?
3. ¿Qué datos suelen faltar o llegar incompletos?
4. ¿Se validan todos los biológicos nuevos o solo algunos?

### 4.2 Validación farmacoterapéutica

5. ¿Qué revisa Farmacia exactamente? (interacciones, dosis, vía, pauta, inducción, ficha técnica, CIMA, especialidades)
6. ¿Quién realiza la validación (farmaceutico/a especialista, residente, otro)?
7. ¿En qué sistema se registra el acto de validación? (JARA, Pharmatool, Excel propio, otro)
8. ¿Se genera un documento o identificador de validación?

### 4.3 Primera visita y seguimiento

9. ¿Existe una primera visita de Farmacia para pacientes en biológico?
10. ¿Qué se registra en esa primera visita?
11. ¿Cómo es el seguimiento longitudinal: frecuencia, variables, responsable?
12. ¿Se realiza adherencia (Morisky-Green u otra), EA, pauta, incidencias?

### 4.4 Interacción con Reumatología

13. ¿Qué devuelve Farmacia a Reumatología tras la validación?
14. ¿Cómo se comunica una alerta o un bloqueante?
15. ¿Quién decide si finalmente se dispensa el fármaco?
16. ¿Qué papel tiene Enfermería en el circuito?

### 4.5 Dolor actual y riesgos

17. ¿Qué parte del circuito consume más tiempo?
18. ¿Dónde hay riesgo de error de seguridad?
19. ¿Qué datos le gustaría recibir estructurados desde Reumatología?

## 5. Preguntas para Enfermería

### 5.1 Rol en el circuito

1. ¿En qué momento interviene Enfermería en el circuito Reuma-Farmacia?
2. ¿Quién educa al paciente sobre el biológico antes del inicio?
3. ¿Quién revisa vacunación, serologías o prebiológico?
4. ¿Se registra algo de este trabajo en algún sistema?

### 5.2 Datos y comunicación

5. ¿Qué datos de Enfermería son útiles para Farmacia?
6. ¿Cómo se comunican adherencia, efectos adversos o incidencias?
7. ¿Quién deriva al paciente a Farmacia cuando detecta un problema?

### 5.3 Oportunidades

8. ¿Qué tareas repetitivas podrían beneficiarse de una digitalización parcial?
9. ¿Dónde hay riesgo de que el sistema asuma decisiones que corresponden a un profesional?

## 6. Preguntas de seguridad clínica y no inferencia

### 6.1 Seguridad clínica (obligatorias)

1. **¿Quién decide la dosis, vía, pauta, presentación e inducción del fármaco?**  
   *Esperado: el médico de Reumatología propone; Farmacia valida farmacoterapéuticamente. El Hub no decide.*

2. **¿Qué ocurre si el catálogo de fármacos del Hub no coincide con la decisión clínica?**  
   *Esperado: prevalece la decisión profesional; el sistema no fuerza una opción.*

3. **¿El Hub debería poder bloquear o autorizar un tratamiento?**  
   *Esperado: no. Puede alertar sobre datos faltantes, pero no sustituye la validación profesional.*

4. **¿Quién asume la responsabilidad si un dato viaja mal entre módulos?**  
   *Esperado: cada profesional sigue responsable de su acto; el Hub es soporte, no responsable clínico.*

5. **¿Cómo se gestiona un efecto adverso comunicado por el paciente?**  
   *Esperado: Enfermería/Reumatología recoge; Farmacia valora; el Hub puede registrar sin inferir causalidad.*

6. **¿Qué datos de paciente real podrían circular por el Hub?**  
   *Esperado: ninguno en fase de diseño/discovery; solo datos sintéticos en demos.*

### 6.2 No inferencia de datos terapéuticos

1. ¿El nombre del fármaco determina automáticamente dosis/pauta en el circuito actual? Si no, ¿por qué el Hub debería hacerlo?
2. Si Reuma envía una solicitud con fármaco X, ¿Farmacia acepta esa solicitud sin revisar dosis/vía/pauta/inducción? ¿Por qué?
3. ¿Existe algún escenario en el que el sistema deba completar automáticamente dosis o pauta a partir del principio activo?
4. ¿Cómo se debe comportar el Hub cuando falte un dato terapéutico: alertar, inferir o bloquear?

> **Principio rector:** el catálogo asiste la selección y normalización, pero nunca decide datos terapéuticos. La ausencia o ambigüedad debe quedar visible y pendiente de confirmación profesional.

## 8. Resultados esperados y próximos pasos

### 8.1 Resultados esperados del discovery

Al finalizar la/s reunión/es se debe obtener:

1. Mapa de proceso Reuma → Farmacia Hospitalaria para Badajoz y Mérida, con pasos, responsables y sistemas actuales.
2. Matriz funcional/localización rellena, diferenciando Badajoz y Mérida si procede.
3. Lista de datos mínimos que Reumatología debe enviar a Farmacia.
4. Lista de datos mínimos que Farmacia debe devolver o compartir con Reumatología.
5. Identificación explícita de quién decide dosis, vía, pauta, inducción, presentación, cambios y suspensiones.
6. Lista de decisiones clínicas que el Hub nunca debe automatizar ni inferir.
7. Acuerdo sobre si Enfermería interviene como nexo y con qué datos.
8. Recomendación de si la interfaz Reuma↔FH requiere una WO posterior de diseño de contrato o si primero se necesitan más reuniones.
9. Documento de descubrimiento archivado en `docs/discovery/` para uso de futuras WO.

### 8.2 Próximos pasos post-discovery

1. Compartir esta guía con los participantes con al menos 48 h de antelación.
2. Recoger notas, audio (si se autoriza) o acta escrita.
3. Completar las plantillas de las secciones 7.1 y 7.2 con la información real.
4. Entregar el resultado a Sil/Cora para decidir si se abre una WO de diseño de contrato Reuma↔FH.
